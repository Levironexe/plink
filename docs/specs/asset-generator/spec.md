# Spec — feat/asset-generator: AI hero/banner/thumbnail images + per-site asset library

Feature G of the Creator Website OS plan
(`docs/superpowers/plans/2026-09-03-creator-website-os.md`, §"Feature G").
Product Plan VI V0 — "AI Asset Generator cho hero, banner và thumbnail";
§4 Asset Pipeline.

## Problem

A site brief arrives with words, never pictures. Today an operator building a
client site has nothing to put in a hero or a card until the client sends
photography, so first drafts stall. `packages/ai/src/assets.ts` is a stub that
throws, and `Asset` rows are only ever written by manual uploads.

Feature G gives the studio one button: describe the image, pick the shape, get
a stored image the site can point at — and a per-site library of everything
generated so far.

## Constitution constraints (binding)

- **I.1** — the route authenticates and scopes by owner. Every read and write
  goes through `requireSite` (`apps/web/src/lib/workspace.ts`); "missing" and
  "not yours" are indistinguishable.
- **I.3** — `AI_GATEWAY_API_KEY` and `BLOB_READ_WRITE_TOKEN` are read at call
  time. The page renders, the app builds and the route answers 503 with a
  configuration message when either is blank.
- **I.4** — generated bytes obey the upload discipline: a MIME **allowlist**
  (PNG/JPEG/WebP; never SVG), the existing 8 MB image ceiling, and a
  traversal-safe key under the owner's `u/<userId>/` prefix.
- **II.3** — the Prisma schema is frozen. `Asset` is consumed exactly as it
  stands (`id, userId, siteId?, kind, url, mimeType, prompt, meta, createdAt`).
- **III.3** — generation is a significant mutation: it writes an `AuditLog`
  row (`asset.generate`) and an `EventLog` row (`asset_generated`).
- **IV.1 / IV.3** — the studio page is admin UI: `@theme` tokens and the
  `.field` / `.card` component classes from `globals.css`, no hardcoded colour.
- **V.1** — `@plink/ai` must not depend on `@plink/storage`. The package
  returns bytes; the app uploads them.
- **VI.2** — behaviour pinned by unit tests with no network and no database.

## Public contract

### `packages/ai/src/assets.ts`

```ts
export const ASSET_KINDS = ["hero", "banner", "thumbnail"] as const;
export type AssetKind = (typeof ASSET_KINDS)[number];

export const ASSET_PROMPT_MAX = 600;
export const ASSET_MIME_TYPES = ["image/png", "image/jpeg", "image/webp"] as const;
export const DEFAULT_IMAGE_MODEL = "google/imagen-4.0-fast-generate-001";

export type GenerateAssetInput = { kind: AssetKind; prompt: string };
export type GeneratedAsset = { bytes: Uint8Array; mimeType: string };

export function isAssetKind(value: unknown): value is AssetKind;
export function assetImageModel(): string;              // AI_IMAGE_MODEL ?? default, read at call time
export function composeAssetPrompt(kind: AssetKind, prompt: string): string;  // pure
export function generateAssetImage(input: GenerateAssetInput): Promise<GeneratedAsset>;
```

**Deviation from the stub (sanctioned, recorded here):** `GeneratedAsset` was
`{ url: string; mimeType: string }`, which implied `@plink/ai` would upload
through `@plink/storage`. That inverts the dependency direction of Article V.1
and makes the function impossible to test without a blob token. The stub is
unreleased and had no callers, so the shape becomes
`{ bytes: Uint8Array; mimeType: string }`. Every other exported name is
unchanged.

`composeAssetPrompt` is pure: it clamps the operator prompt with the existing
`clampText` (600 chars, control characters stripped) and wraps it in a
kind-specific framing plus shared house rules (no text in the image, no logos,
no watermarks, no recognisable faces). Same input, same output, no I/O.

`generateAssetImage`, in order:

1. `aiEnabled()` false → `throw new Error("AI is not configured")`;
2. unknown `kind` → throws naming the kind;
3. prompt that clamps to empty → throws asking for a description;
4. calls the installed AI SDK's `generateImage` (see
   `docs/spikes/2026-09-03-ai-sdk-image-generation.md`) with the model id from
   `assetImageModel()`, the composed prompt, the kind's aspect ratio
   (`hero`/`banner` → `16:9`, `thumbnail` → `1:1`), `n: 1`, one retry and a
   60 s abort;
5. any SDK/gateway throw → rethrown as one clear sentence naming the model,
   never a stack trace and never key material;
6. an empty result, a zero-byte image or a `mediaType` outside
   `ASSET_MIME_TYPES` → its own clear error;
7. otherwise returns `{ bytes, mimeType }`.

### `apps/web/src/app/api/assets/route.ts`

`runtime = "nodejs"`, `maxDuration = 60`.

**POST** `{ siteId, kind, prompt }`

| Step | Failure |
| --- | --- |
| IP rate limit (12 / 10 min) | 429 |
| body shape; `kind` ∈ `ASSET_KINDS`; `prompt` 1…600 | 422 |
| `requireSite(siteId)` | 401 / 403 via `storeErrorResponse` |
| per-user rate limit (20 / 60 min) | 429 |
| `aiEnabled()` | 503 |
| `uploadEnabled()` | 503 (`UPLOAD_NOT_CONFIGURED_MESSAGE`) |
| `generateAssetImage` | 502 with the generator's message |
| MIME allowlist + `MAX_IMAGE_BYTES` | 502 |
| `putObject` | 502 |

On success: uploads to
`u/<userId>/ai-asset/<siteId>/<kind>-<random>.<ext>` — the owner prefix comes
from `userPrefix()`, the leaf from `slugifyFilename()`, and the site segment is
scrubbed to `[A-Za-z0-9_-]{1,64}`, so no part of the key can escape the
caller's prefix (I.4, and `ownsObject` keeps working for a later delete).
Then creates `Asset { userId, siteId, kind: "ai", url, mimeType, prompt,
meta: JSON.stringify({ assetKind }) }`, writes audit `asset.generate` and event
`asset_generated`, and returns `{ asset }` — `{ id, kind, assetKind, url,
mimeType, prompt, createdAt }`.

**GET** `?siteId=…` → `requireSite`, then that site's `Asset` rows newest first
as `{ assets }` (same serialised shape). `assetKind` is read back out of `meta`
and defaults to `"hero"` when the row was not written by this feature.

### `/studio/[siteId]/assets`

Server page: `requireSite` (throws → `/login` on `UNAUTHENTICATED`, `notFound()`
otherwise), loads the site's assets, and renders a client panel with the site
name, the kind picker, the prompt textarea, a generate button with a pending
state, and the gallery grid (image, kind badge, prompt, created date, copy-URL
button). When `aiEnabled()` is false the form is replaced by a "not configured"
card and the existing gallery still renders. Everything is `.field` / `.card`
and `@theme` tokens; the file lives in that route's own `_components/`
(Article V.2).

## Out of scope

- **Applying an asset into the site document.** The editor agent owns document
  mutations; copy-URL is the v1 bridge between the library and the editor.
- Deleting or regenerating an asset, image-to-image edits, moderation review
  queues, and any Prisma schema change.
- Uploading a file by hand — `/api/upload` already does that.
